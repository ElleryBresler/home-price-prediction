# Field Sources Data Dictionary

This document identifies the source, derivation, and purpose of the fields in `sql/schema.sql`. It describes the data sources, transformations, relationships, and machine-learning fields used throughout the home price prediction project.

## Model Results Tables

### `model_evaluation_metrics`

This table stores model evaluation metrics for different models and datasets.

| Field | Comes from | How | Used for |
|---|---|---|---|
| `evaluation_id` | Generated by PostgreSQL | Automatically generated identity value | Primary key; uniquely identifies each evaluation record |
| `model_name` | Model training and evaluation process | Name of the evaluated model | Identifies which model was evaluated |
| `evaluation_date` | Generated by PostgreSQL | Automatically assigned current timestamp | Records when the evaluation occurred |
| `dataset_name` | Model evaluation process | Identifies the dataset used for evaluation | Distinguishes the dataset associated with the evaluation |
| `mae` | Model evaluation process | Mean Absolute Error | Measures the average absolute difference between actual and predicted values |
| `rmse` | Model evaluation process | Root Mean Squared Error | Measures prediction error while placing greater weight on larger errors |
| `r_squared` | Model evaluation process | R-squared evaluation metric | Measures the proportion of target variation explained by the model |

### `home_price_predictions`

This table stores one prediction per home sale for the selected Gradient Boosting model. It includes predictions for the training, validation, and test datasets.

| Field | Comes from | How | Used for |
|---|---|---|---|
| `prediction_id` | Generated by PostgreSQL | Automatically generated identity value | Primary key; uniquely identifies each prediction record |
| `sale_id` | `fact_home_sale.sale_id` | Links each prediction to its original home sale | Foreign key; identifies the home associated with the prediction |
| `split` | `ml_feature_table.split` | Identifies whether the record belongs to the train, validate, or test dataset | Distinguishes predictions by dataset split |
| `actual` | `ml_feature_table.sale_price` | Actual recorded home sale price | Reference value used to evaluate prediction accuracy |
| `predicted` | Gradient Boosting model | Predicted sale price generated by the selected model | Model output; estimated home sale price |
| `error` | Calculated in Python | Actual sale price minus predicted sale price | Measures prediction error; positive values indicate underprediction and negative values indicate overprediction |
| `model_name` | Model selection process | Stores the selected model name, Gradient Boosting | Identifies which model generated the prediction |

The model script clears and rebuilds the `home_price_predictions` table each time it runs. It generates one prediction for each of the 1,460 housing records:

- 947 training records
- 338 validation records
- 175 test records

All predictions currently stored in this table were generated by the selected Gradient Boosting model.

## Source Fields Used but Not Stored

- **Ames Housing Dataset:** `Id`, `Neighborhood`, `YrSold`, `MoSold`, `OverallQual`, `GrLivArea`, `BedroomAbvGr`, `FullBath`, `YearBuilt`, `GarageCars`, and `SalePrice` are mapped to fields in the database schema.
- Additional Ames fields remain in the original local `train.csv` but are not currently included in the database schema.
- **Census API:** The extraction script retrieves `NAME`, `B19013_001E`, `B01003_001E`, and `B15003_022E`, along with geographic identifiers. The demographic values represent Ames, Iowa, as a whole, not individual neighborhoods.
- **FRED API:** The extraction script retrieves observations for the `MORTGAGE30US` series. Observation dates and source metadata are retained in the raw JSON response. Inflation and unemployment series are outside the current project scope.

## Machine-Learning Feature Table

The `ml_feature_table` contains one row per home sale, with the target and joined features needed for modeling. It is built by `etl/build_features.py` from the fact and dimension tables.

| Field or field group | Source or derivation | Purpose |
|---|---|---|
| `sale_id` | `fact_home_sale.sale_id` | Unique identifier for each prediction record |
| Property features | `dim_property` | Describe quality, size, bedrooms, bathrooms, construction year, and garage capacity |
| `house_age_at_sale` | Calculated in Python as `sale_year - year_built` | Derived model feature representing the home's age when it was sold |
| Location features | `dim_location` | Provide Census demographics and neighborhood information |
| Date features | `dim_date` | Provide sale year, month, and quarter |
| `mortgage_rate` | `fact_economic_conditions` | Represent the mortgage rate associated with the sale month |
| `sale_price` | `fact_home_sale.sale_price` | Target variable |
| `neighborhood_*` | One-hot encoding of `neighborhood` in Python | Represent neighborhood categories numerically |
| `split` | Derived from `sale_year` in Python | Assign records to training, validation, or test data |

Two numeric features are derived during feature engineering: `sale_quarter`, calculated from the sale month, and `house_age_at_sale`, calculated by subtracting the construction year from the sale year. The categorical `neighborhood` field is also one-hot encoded into 25 binary columns.

The chronological split assigns sales from 2006–2008 to training, 2009 to validation, and 2010 to testing. The resulting table contains 1,460 records: 947 training, 338 validation, and 175 testing records.

The Census demographic values describe Ames, Iowa, as a whole rather than individual neighborhoods. Mortgage rates are joined by the sale's year-month key. These geographic and temporal limitations should be considered when interpreting model results.
