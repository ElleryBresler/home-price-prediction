## Fact Tables

| Table | Field | Comes from | How | Used for |
|---|---|---|---|---|
| `fact_economic_conditions` | `economic_id` | Generated by PostgreSQL | Automatically generated identity value | Primary key |

## Source Fields Used but Not Stored

- **Ames Housing Dataset:** `Id`, `Neighborhood`, `YrSold`, `MoSold`, `OverallQual`, `GrLivArea`, `BedroomAbvGr`, `FullBath`, `YearBuilt`, `GarageCars`, and `SalePrice` are mapped to fields in the database schema.
- Additional Ames fields remain in the original local `train.csv` but are not currently included in the database schema.
- **Census API:** The extraction script retrieves `NAME`, `B19013_001E`, `B01003_001E`, and `B15003_022E`, along with geographic identifiers. The demographic values represent Ames, Iowa, as a whole, not individual neighborhoods.
- **FRED API:** The extraction script retrieves observations for the `MORTGAGE30US` series. Observation dates and source metadata are retained in the raw JSON response. Inflation and unemployment series are outside the current project scope.

## Machine-Learning Feature Table

The `ml_feature_table` contains one row per home sale, with the target and joined features needed for modeling. It is built by `etl/build_features.py` from the fact and dimension tables.

| Field or field group | Source or derivation | Purpose |
|---|---|---|
| `sale_id` | `fact_home_sale.sale_id` | Unique identifier for each prediction record |
| Property features | `dim_property` | Describe quality, size, bedrooms, bathrooms, construction year, and garage capacity |
| `house_age_at_sale` | Calculated in Python as `sale_year - year_built` | Derived model feature representing the home's age when it was sold |
| Location features | `dim_location` | Provide Census demographics and neighborhood information |
| Date features | `dim_date` | Provide sale year, month, and quarter |
| `mortgage_rate` | `fact_economic_conditions` | Represent the mortgage rate associated with the sale month |
| `sale_price` | `fact_home_sale.sale_price` | Target variable |
| `neighborhood_*` | One-hot encoding of `neighborhood` in Python | Represent neighborhood categories numerically |
| `split` | Derived from `sale_year` in Python | Assign records to training, validation, or test data |

Two numeric features are derived during feature engineering: `sale_quarter`, calculated from the sale month, and `house_age_at_sale`, calculated by subtracting the construction year from the sale year. The categorical `neighborhood` field is also one-hot encoded into 25 binary columns.

The chronological split assigns sales from 2006–2008 to training, 2009 to validation, and 2010 to testing. The resulting table contains 1,460 records: 947 training, 338 validation, and 175 testing records.

The Census demographic values describe Ames, Iowa, as a whole rather than individual neighborhoods. Mortgage rates are joined by the sale's year-month key. These geographic and temporal limitations should be considered when interpreting model results.
